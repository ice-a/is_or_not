# 「辨是非」小程序架构方案（MVP 可快速上线版）

> 定位：面向老年用户的「粘贴即判」谣言 / 骗局识别工具
> 技术栈：小程序原生 + 微信云开发（CloudBase）+ 第三方大模型 API
> 目标：14 天内可提审上线，架构可平滑扩展到百万级查询

---

## 0. 一句话结论与选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生小程序（不用 Taro/uni-app） | MVP 只有 4 个页面，跨端框架反而拖慢；后续要接 Skyline 与 TDesign 也无缝 |
| 后端 | **微信云开发云函数 + 云数据库 + 云存储** | 免服务器、免备案运维、天然 `openid` 鉴权、数据库 `watch` 实时推送（省掉轮询与 WebSocket） |
| AI | 云函数中转调用第三方大模型（DeepSeek / 豆包 / 混元 可切换） | 不在小程序端暴露 Key；服务端可换模型、可降级、可审计 |
| 事实佐证 | 官方辟谣库本地匹配（主）+ 搜索引擎检索（辅） | 官方源优先保证权威；检索只做兜底，且必须人工/规则过滤后再呈现 |
| 缓存 | 云数据库 `verdicts` 集合 + 内容指纹 | 谣言高度重复传播，缓存命中率预期 40%+，直接省掉 AI 成本且秒开 |

**架构主线一句话**：用户粘贴 → 云函数做「合规检查 + 指纹查缓存」→ 未命中则解析链接 → 四阶段 AI 判定 → 官方源佐证 → 老年化改写 → 写库 → 前端 `watch` 实时拿到结果。

## 1. 总体架构

```
┌─────────────── 小程序端（原生） ───────────────┐
│  home(粘贴入口)  result(结论)  history  mine   │
│  大字模式 / 语音播报 / 分享卡片 / 反馈纠错      │
└───────────┬──────────────────────┬────────────┘
            │ wx.cloud.callFunction │ db.watch()
            ▼                       ▼
┌─────────────── 云开发 CloudBase ───────────────┐
│ 云函数：                                        │
│  ├ analyze      提交任务/查缓存/合规前置         │
│  ├ dispatcher   定时触发器，驱动异步 pipeline    │
│  ├ resolveLink  链接→文案（多适配器）           │
│  ├ aiAnalyze    四阶段大模型调用                │
│  ├ verify       官方库匹配 + 多源检索           │
│  └ user/history/feedback/share                  │
│ 云数据库：users jobs verdicts sources feedback  │
│ 云存储：分享卡片图 / TTS 音频                   │
└───────────┬────────────────────────────────────┘
            │ HTTPS（服务端出网）
            ▼
   大模型 API ｜ 网页抓取 ｜ 搜索引擎 ｜ 官方辟谣源
```

**关键设计决策：异步任务 + `watch` 实时推送**
云函数单次最长 60s，而「解析 + AI + 检索」链路可能超时。所以主流程拆成：

1. `analyze` 云函数 300ms 内返回 `jobId`（同步）
2. 后台 pipeline 写 `jobs.status`，前端 `db.collection('jobs').doc(jobId).watch()` 实时收进度
3. `watch` 不可用时降级为 2s 轮询（自动探测切换）

> ⚠️ 约束：单页面只保留 1 个 `watch`，`onUnload` 必须 `close()`，否则监听数超限报错。

## 2. 前端页面结构与交互流程

### 2.1 页面清单（MVP 4 页 + 1 tabBar）

```
pages/
├── home/       首页：粘贴入口（tabBar）
├── result/     结论页（非 tab，可分享直达）
├── history/    历史记录（tabBar）
└── mine/       我的：长辈模式 / 关于 / 免责（tabBar）
components/
├── big-input/       超大粘贴框 + 一键粘贴按钮
├── progress-card/   分阶段加载卡（拟人化文案）
├── verdict-card/    结论徽标 + 一句话 + 三条理由
├── source-list/     官方来源（仅白名单域名可点）
└── share-sheet/     生成分享卡片
```

**tabBar 只放 3 项**（老年用户认知负荷最小化）：`查一查` / `历史` / `我的`。

### 2.2 首页交互流程（状态机）

```
[空态] ──粘贴/输入──> [可提交] ──点击"帮我看看"──> [合规检查中]
                                                      │
                        ┌─────────────────────────────┤
                        ▼                             ▼
                 [命中缓存：直接跳结果]        [创建任务 → 进度态]
                                                      │
   阶段文案（每阶段 ≥1.2s，避免闪屏）：
   ① "正在读你发的内容…"        (resolveLink)
   ② "正在查证是不是真的…"      (aiAnalyze)
   ③ "正在找官方说法…"          (verify)
   ④ "正在把话说简单…"          (simplify)
                                                      ▼
                                        [结果页] / [降级页]
```

**输入形态自动识别**（不需要用户选择类型，减少操作步骤）：

| 输入特征 | 判定 | 处理 |
|---|---|---|
| 含 `xiaohongshu.com` / `xhslink.com` | 小红书 | 解析 + 提示"最好把文字也复制进来" |
| 含 `douyin.com` / `v.douyin.com` / `iesdouyin` | 抖音 | 短链还原 + 取分享文案 |
| 含 `mp.weixin.qq.com` | 公众号 | 抓标题 + 正文摘要 |
| 纯 `http(s)://` | 网址 | 通用正文抽取 |
| 含"【】"、106 号段、无链接短文本 | 短信 | 直接送 AI |
| 其他 | 纯文本 | 直接送 AI |

### 2.3 结果页：老年化输出规格（硬约束）

结果页**只允许 3 档结论**，禁止出现百分比、置信度数字、专业术语：

| 档位 | 展示 | 配色 |
|---|---|---|
| 假 | ❌ **这是假的，别信别转** | 红底白字 |
| 真 | ✅ **基本可信** | 绿底白字 |
| 说不准 | ❓ **还没查清，先别动手** | 黄底黑字 |

**版面固定 5 块，从上到下：**

1. **结论徽标**（≥ 32px 字，全屏最顶部，一屏内可见）
2. **一句话结论**：≤ 30 字，口语。例：
   - ✅ 真："这条说的是真的，国家确实发了这个文件。"
   - ❌ 假："这是假的，官方根本没有这个说法，别转给家人。"
   - ❓ 存疑："这事儿现在查不清，先别转钱、别点链接。"
3. **为什么说**（≤ 3 条，每条 ≤ 20 字，带图标）
   - "没找到任何官方通知"
   - "让你先交钱才办事，正规机构不会这样"
   - "发的人说不出具体出处"
4. **你该怎么办**（≤ 2 条行动指令，动词开头）
   - "别点里面的链接"
   - "拿不准就打 96110 问一问"
5. **出处**（可折叠，最多 3 条，只显示机构名 + 标题，域名白名单才可跳转）
   - 中国互联网联合辟谣平台 / 国家反诈中心 / 12321 / 当地政府门户 / 央视新闻…

**底部固定操作条**：`🔊 读给我听` ｜ `📤 发给家人` ｜ `👎 说错了`（反馈纠错）

> "读给我听"：云函数调腾讯云 TTS 生成 mp3 存云存储，`InnerAudioContext` 播放（P1 阶段上线，MVP 用大字号替代）。

### 2.4 历史记录

- 写入：`analyze` 成功后本地 `wx.setStorageSync` 立即落一条（离线可读），云端异步同步
- 展示：按时间倒序，**只显示「一句话结论 + 结论徽标 + 时间」**，点进详情看完整
- 容量：本地保留最近 50 条，云端保留 90 天后归档
- 交互：左滑删除、顶部搜索（按关键词）+ 筛选（只看"假的"）

```css

  --fs-base: 18px;      /* 正文，≥18px，系统默认 16 偏小 */
  --fs-title: 22px;

  --tap-min: 56px;      /* 最小点击热区，≥56×56 */

}
/* mine 页「长辈模式」开关 → 根节点加 .elder，字号整体 ×1.35，行高 1.9 */
```

其他硬性要求：
- 主按钮固定在页面底部 `safe-area`，不用悬浮小按钮
- 禁止自动弹出订阅消息授权（审核风险 + 老年用户误点）

- 加载态文案不用"Loading…"，用"正在帮您看…"

## 3. 后端 / 云函数架构

### 3.1 云函数清单

| 云函数 | 触发 | 超时 | 职责 |
|---|---|---|---|
| `analyze` | 前端调用 | 20s | 合规前置 → 内容指纹 → 查缓存 → 未命中建 job 返回 jobId |
| `pipeline` | 定时器 1s（或 `analyze` 内 `cloud.callFunction` 异步触发） | 60s | 编排：resolve → ai → verify → simplify → 写 verdicts |
| `resolveLink` | pipeline 内调用 | 15s | 多适配器抽文案 |
| `aiAnalyze` | pipeline 内调用 | 55s | 四阶段大模型调用，返回严格 JSON |
| `verify` | pipeline 内调用 | 20s | 官方辟谣库匹配 + 检索兜底 |
| `history` / `feedback` / `shareCard` | 前端调用 | 10s | 历史同步 / 纠错 / 生成分享图 |
| `quotaGuard` | 被 analyze 内联 | — | 限流与配额（见 §4.4） |

> MVP 简化：可把 `pipeline/resolveLink/aiAnalyze/verify` 合并成一个 `worker` 云函数，用定时触发器扫 `jobs` 中 `status=pending` 的记录。代码量小、排障简单；量起来后再拆分。

### 3.2 异步驱动方式（推荐 MVP 方案）

```
analyze(同步, <1s)
  ├ msgSecCheck 通过?
  ├ 指纹 = sha256(normalize(text)) 前16位
  ├ verdicts 命中? → 直接返回 {cached:true, verdict}
  └ 否则 → jobs.add({status:'pending', stage:0}) → 触发 worker
                                                     │
worker(定时触发器 或 云调用异步)                      │
  stage 1→4，每步 jobs.update({stage, status})        │
                                                     │
前端 watch(jobs/jobId) ── onChange ──> 渲染进度/结果 ─┘
```

前端代码骨架：

```js
// pages/home/home.js
Page({
  data: { jobId: '', stage: 0, stageText: '', done: false },
  async onSubmit(text) {
    wx.showLoading({ title: '正在帮您看…' });
    const { result } = await wx.cloud.callFunction({
      name: 'analyze', data: { text }
    });
    wx.hideLoading();
    if (result.cached) return wx.navigateTo({ url: `/pages/result/result?id=${result.verdictId}` });
    this.setData({ jobId: result.jobId });
    this.watcher = db.collection('jobs').doc(result.jobId).watch({
      onChange: snap => {
        const job = snap.doc;
        this.setData({ stage: job.stage, stageText: STAGE_TEXT[job.stage] });
        if (job.status === 'done')    { this.watcher.close(); wx.redirectTo({url:`/pages/result/result?id=${job.verdictId}`}); }
        if (job.status === 'degraded'){ this.watcher.close(); wx.redirectTo({url:`/pages/result/result?id=${job.verdictId}&dg=1`}); }
      },
      onError: () => this.fallbackPoll()   // 降级 2s 轮询
    });
  },
  onUnload() { this.watcher && this.watcher.close(); }
});
```

### 3.3 AI 调用链路（四阶段，两路并行）

```
           ┌── 阶段A 抽取（extract）─────────┐
输入文本 ──┤   主张 / 主体 / 诉求动作 / 情绪  ├──→ 阶段B 定级
           └── 阶段C 佐证检索（并行）────────┘       ↓
                   官方库 + 搜索                真 / 假 / 存疑 + 命中特征
                                                      ↓
                                          阶段D 老年化改写（simplify）
                                                      ↓
                                          严格 JSON → 校验 → 写库
```

- **阶段 A + C 并行**：抽取和检索互不依赖，节省 30%~40% 延迟
- **阶段 B** 依赖 A+C 的结果（先内判定，再与外部证据交叉；**冲突一律降级为"说不准"**，禁止硬下结论）
- **阶段 D** 单独一次调用，prompt 专门做口语化，避免前面阶段被"既要分析又要通俗"拖累质量
- 未命中任何已知套路 **且** 语义高压/胁迫/要求保密 → 不判"真"，主动广谱检索后标"疑似新型套路，建议 96110 核实"

**统一出参 JSON Schema（阶段 B/C 输出，强制 `response_format: json_object`）**

```json
{
  "claim": "这条内容在说什么（20字内）",
  "verdict": "false | true | unverified",
  "channel": "sms | xhs | douyin | wemp | web | text",
  "intent": "传播目的：带货 / 引流 / 骗钱 / 吓唬人 / 单纯转述",
  "reasons": ["≤20字", "≤20字", "≤20字"],
  "actions": ["动词开头≤12字", "≤12字"],
  "riskPredicates": ["R5_要求转账", "Y9_免费引流"],
  "evidence": {
    "matchedOfficial": true,
    "conflict": false,
    "sources": [{ "org": "中国互联网联合辟谣平台", "title": "...", "url": "..." }]
  },
  "confidenceInternal": "high | mid | low",
  "oneLine": "≤30字口语结论"
}
```

> `confidenceInternal` **不展示给用户**，只用于内部排序与是否触发人工复核。

**老年化 prompt 关键片段（阶段 D）**

```
你是给 60 岁以上老人解释消息的社区工作者。
规则：
1. 只用小学四年级能听懂的话，禁止出现"权威""置信度""话术""诱导""链路"等词
2. 一句话结论不超过 30 个字，必须直接回答"真的还是假的"
3. 理由最多 3 条，每条不超过 20 字
4. 行动建议必须是一个具体动作，动词开头，不超过 12 字
5. 涉及钱/验证码/链接时，结论必须写成"别转钱""别点链接""别把验证码告诉别人"
6. 查不清就说"现在查不清"，不许猜
输出严格 JSON，不要任何解释性文字。
```

### 3.4 链接解析方案（FetchAdapter 矩阵）

| 渠道 | 解析方式 | 成功率预期 | 失败降级 |
|---|---|---|---|
| 公众号文章 | 服务端 GET + 正则/cheerio 抽 `og:title`、`og:desc`、正文前 1500 字 | 高（85%） | 用标题继续分析 |
| 普通网址 | 通用正文抽取（Readability 思路）+ 反爬 UA | 中（70%） | 提示"复制文字给我" |
| 抖音 | 短链 `v.douyin.com` → 跟随 302 → 取分享页 `<title>`（含视频文案） | 中（60%，有风控） | 引导复制"分享文案" |
| 小红书 | 无公开接口，网页有强风控 | **低（<40%）** | **MVP 直接引导用户复制笔记正文**，不做强依赖 |
| 短信 | 纯文本，无需解析 | 100% | — |

**统一约束：**
- 所有抓取必须设 5s 超时 + 1 次重试；禁止无限跟随跳转（最多 3 跳）
- 抓取结果只用于 AI 分析，**不落库、不展示原文给用户**（版权 + 合规）
- 尊重 `robots.txt`；对明确禁止抓取的站点直接走"请复制文字"引导
- 抖音/小红书解析做成**可开关配置**，被风控时一键关闭，不影响主流程

### 3.5 结果缓存策略

```
指纹 key = sha256( normalize(text) )[:16]
normalize：去空白/去表情/去链接参数/繁转简/去"【】"短信前缀
```

- **精确命中**：`verdicts` 直接返回，0 AI 成本，秒开（目标 P95 < 800ms）
- **相似命中**：对前 200 字算 SimHash，汉明距离 ≤ 3 视为同一条（对付"转发时改几个字"）
- **TTL 分层**：
  - 判为"假"：7 天（谣言会变异，需定期复检）
  - 判为"真"：30 天
  - 判为"说不准"：24 小时（鼓励重新检索，可能已出官方通报）
- **复检**：定时触发器每天扫 `verdicts` 中过期且查询次数 Top100 的条目，重新走 verify 阶段（不重跑完整 AI）
- **负面缓存**：抓取失败也缓存 5 分钟，防止同一条被反复重试打爆

### 3.6 失败降级（三级，永不空白返回）

| 级别 | 触发条件 | 返回内容 |
|---|---|---|
| **L1 部分降级** | 链接抓取失败，但拿到标题/URL | 正常走 AI，结果页顶部灰条提示"没能读到全文，只看懂了标题，建议您把文字也复制进来" |
| **L2 AI 降级** | 大模型超时/5xx/返回非法 JSON | 走**规则引擎**：关键词黑名单 + 官方辟谣库全文匹配 + 反诈五要素谓词表 → 能定级就定级，不能则"说不准"，标 `[规则判定，未经AI复核]` |
| **L3 全降级** | AI 与规则引擎都失败 | 直接输出**「自查清单」**：这条消息——①谁发的？②让你干啥？③要钱吗？④要你点链接/下载吗？⑤在催你吗？→ 命中 2 条以上就别信，打 96110 问。并给"稍后再试"按钮 |

额外：
- 任何阶段失败都必须 `jobs.update({status:'degraded', errStage})`，前端不卡 loading
- 大模型侧：主模型失败 → 30s 内自动切备用模型（配置化 `MODEL_CHAIN`），仅重试 1 次
- 前端看门狗：35s 未完成自动跳 L3 页，并后台继续等待，结果出来后发订阅消息/历史红点

## 4. 数据模型与接口设计

### 4.1 云数据库集合

```
users        _id, openid(uniq), createdAt, quota{used, bonus, resetAt}, elderMode, lastActiveAt
jobs         _id, openid, inputType, rawText(hash), stage, status(pending|running|done|degraded|failed),
             errStage, verdictId, createdAt, updatedAt
verdicts     _id, fingerprint(uniq), simhash, channel, claim, verdict, intent,
             oneLine, reasons[], actions[], sources[], riskPredicates[],
             confidenceInternal, model, hitCount, expiresAt, createdAt
sources      _id, org, title, url, domain(白名单), credibility(官方1.0/媒体0.7), fetchedAt
feedback     _id, openid, verdictId, type(wrong|inaccurate|good), comment, createdAt
abuse        _id, openid/ip, day, count, lastAt      // 限流计数
```

**索引（必建，否则量起来慢查询）：**
- `users`: `openid` unique
- `jobs`: `openid + createdAt desc`、`status + createdAt`（worker 扫描用）
- `verdicts`: `fingerprint` unique、`expiresAt`、`hitCount desc`
- `feedback`: `verdictId`

### 4.2 接口（云函数即接口，`event` 即 body）

| 接口 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `analyze` | `{text}` | `{cached, verdictId}` 或 `{jobId}` | 唯一写入口，含合规+限流 |
| `getVerdict` | `{verdictId}` | `verdict 全量` | 结果页/分享直达 |
| `listHistory` | `{page, size, filter}` | `{items[], hasMore}` | 分页 20 |
| `delHistory` | `{ids[]}` | `{ok}` | 软删除 |
| `submitFeedback` | `{verdictId, type, comment}` | `{ok}` | 纠错入口，进人工复核队列 |
| `genShareCard` | `{verdictId}` | `{fileID}` | 云存储图片（带小程序码） |
| `setElderMode` | `{on}` | `{ok}` | 偏好同步 |

**统一返回结构**

```json
{ "ok": true, "code": 0, "data": {}, "msg": "" , "traceId": "..." }
{ "ok": false, "code": 4001, "msg": "今天次数用完啦，明天再来", "traceId": "..." }
```

### 4.3 鉴权

- **不做自建登录体系**。云函数内 `cloud.getWXContext()` 直接拿 `OPENID`，天然可信，前端不可伪造
- 敏感操作（删除历史、反馈）一律在云函数内用 `openid` 过滤，前端传的 `openid` 一律忽略
- 结果页支持分享直达（他人打开）→ `verdictId` 是随机 ID 不可枚举（不用自增），且**只返回结论，不返回原始输入文本**
- 若后期接 App/网页端，再加 JWT 网关层，云函数内做 `openid | uid` 双通道

### 4.4 接口防刷与配额

```
                ┌─ 单用户：每日 N=10 次（免费）──┐
analyze 入口 →  ├─ 单用户：每分钟 ≤ 3 次          ├→ 拒绝并提示
                ├─ 单 IP：每分钟 ≤ 30 次          ├
                ├─ 内容指纹重复：不扣次数          ├
                └─ 新用户首日：+5 次奖励          ┘
```

- 计数存 `abuse` 集合，云函数内原子 `inc`（用 `_.inc(1)`），不用读-改-写
- 配额用尽不硬报错，给**增长钩子**："分享给家人群可再得 5 次"（分享回调校验后加次数）
- 恶意输入（<5 字、纯乱码、广告刷屏）→ 不进 AI，直接提示"内容太短，说不清楚"
- 成本熔断：全局每日 AI 调用预算上限（如 ¥200），超限自动切规则引擎，并告警到运维群

### 4.5 内容合规与安全

**输入侧（必须，硬门禁）**
1. `wx.cloud.openapi.security.msgSecCheck` —— 用户粘贴的文本**先过检再入库**，命中违规直接拒绝并提示
2. 长度截断：≤ 5000 字，超出截取前 3000 + 后 1000
3. 个人信息脱敏：正则识别手机号/身份证/银行卡/住址 → 送 AI 前打码，日志中亦不落原文

**输出侧**
1. AI 生成的 `oneLine / reasons / actions` 同样过 `msgSecCheck`
2. 来源 URL 走**域名白名单**（gov.cn / 12321.cn / piyao.org.cn / 主流媒体），非白名单只显示机构名，不可点击
3. 结果页显著位置标注 **"本结论由人工智能生成，仅供参考"**（《人工智能生成合成内容标识办法》要求，显式标识）

**数据与隐私**
- 原始输入文本**加密存储且 30 天后自动清理**，`verdicts` 只留 `claim`（摘要）不留存原文全文
- 不在任何日志里打印 `rawText` / `openid` 明文
- 隐私政策中明确：用于识别的内容可能经第三方大模型处理，并给出拒绝选项

## 5. 微信小程序审核与合规要点

**必过项（提审前自检清单）**

| # | 项 | 说明 |
|---|---|---|
| 1 | **类目选择** | 选「工具 → 信息查询」或「教育 → 教育信息服务」。**不要选**「医疗」「新闻资讯」，后者需资质 |
| 2 | **ICP 备案** | 2023-09 起新小程序必须先完成备案才能上架，预留 5–10 个工作日 |
| 3 | **AI 生成标识** | 结果页显式标注"AI 生成"字样 + 用户协议中说明，符合 2025-09-01 施行的标识办法 |
| 4 | **算法/大模型备案** | 使用已备案的第三方大模型 API（DeepSeek/豆包/混元/通义）通常无需自建算法备案，但**需在协议中披露所用模型**；若自训练模型则必须备案。建议上线前与平台/法务确认一次 |
| 5 | **免责声明** | 显著位置写"本工具结论由 AI 生成，不构成法律/医疗/投资建议，请以官方通报为准" |
| 6 | **内容安全机制** | 必须接入 `msgSecCheck`/`imgSecCheck`，审核时会查；用户可举报入口要有 |
| 7 | **隐私协议** | 小程序后台配置《用户隐私保护指引》，声明采集内容（剪贴板）用途 |
| 8 | **不以官方自居** | 措辞禁止"官方辟谣""权威认定"，改为"目前没有找到官方依据""据 XX 网站 2026-09 通报" |
| 9 | **杜绝诱导分享** | 分享解锁次数的文案不能写成"不分享就不能用"，只能写"分享可多得 5 次" |
| 10 | **无外部跳转** | 结果页不允许跳 H5、不允许跳外链 App；来源只显示文本，点击走 `webview` 需业务域名备案（建议 MVP 不做跳转） |

**易被驳回的坑**
- 结论中出现"诈骗""违法"定性 → 改为"存在较高风险""建议先核实"，定性权留给监管
- 抓取公众号/抖音内容做展示 → 只做分析，不展示原文，避免侵权投诉
- 用"96110""国家反诈中心"字样做 logo/标题 → 不得冒用官方标识
- 老年用户 + 健康类谣言（如"XX 食物致癌"）→ 涉及医疗健康结论必须弱化为"建议咨询医生"，否则按医疗内容审核

## 6. MVP 范围与分期

### P0 · 14 天提审版（核心闭环）

**做**
- 首页粘贴入口 + 进度态 + 结果页（3 档结论、一句话、3 理由、2 动作）
- 纯文本 / 短信 两种输入（**不做任何链接抓取**）
- AI 两阶段：定级 + 老年化改写（先不做检索佐证，来源用手维护的 20 条官方辟谣库匹配）
- 本地历史记录（Storage）
- 内容指纹缓存 + L2/L3 降级
- 合规：msgSecCheck、AI 标识、隐私协议、免责声明

**不做**：分享、语音、云端同步、检索、抖音/小红书解析、用户体系

> 埋点必须做：提交量、缓存命中率、AI 平均耗时、降级率、反馈"说错了"比例 —— 这 5 个数决定 P1 做什么。

### P1 · +2 周（可信度与留存）

- 公众号文章 / 普通网址解析（成功率高的先做）
- 官方辟谣库扩充到 200+ 条 + 定时同步（中国互联网联合辟谣平台、12321）
- 云端历史同步 + 跨设备
- 分享卡片（带小程序码，家庭群传播主路径）
- 语音播报（TTS）
- 反馈纠错 → 人工复核后台（最简版：云开发 CMS / 数据表格）

### P2 · +3 周（差异化）

- 抖音短链 + 小红书文案解析（带开关，风控即关）
- 多源检索佐证（搜索引擎聚合，结果只做"有没有官方通报"的判别，不直接引用内容）
- 「帮家人查」：生成一条可转发的结果链接
- 高频谣言预警：同一指纹 24h 内查询 >50 次 → 主动推订阅消息（需先取得授权）
- 老年用户误触保护：危险操作二次确认 + 慢速引导动画

### P3 · 增长与商业化

- 公众号联动（每日一条"今日辟谣"）→ 小程序导流
- 社区互助：用户标记"我也收到了"，形成谣言热度榜
- 子女端小程序 / 家庭守护（同一 openid 绑定亲情号）
- 变现（谨慎）：绝不靠"付费解锁真相"；可走政务/媒体合作、公益基金、企业反诈培训

## 7. 增长设计（架构预留位）

1. **结果即传播**：结果卡片底部固定生成带小程序码的分享图，文案是"我帮您查了，这条是假的"—— 家庭群天然传播
2. **零摩擦进入**：老人不会打字，主推"长按复制后打开小程序自动读取剪贴板"（需明确隐私提示），把操作步骤从 6 步压到 2 步
3. **配额即激励**：免费 10 次/天 + 分享 +5，成本可控且带裂变
4. **热点劫持**：缓存命中率高的条目自动进"大家都在查"榜单，首页展示 Top5，制造从众安全感
5. **数据飞轮**：`feedback` 中"说错了"的样本 → 人工复核 → 回流为规则库 + 官方源条目，判定准确率随量提升

## 9. 已知风险与待确认项

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 大模型把真判成假，引发投诉 | 结论只用 3 档，"假"必须附官方来源；无来源强制降为"说不准"；结果页一键纠错 |
| R2 | 抖音/小红书抓取被风控 | MVP 不依赖，引导复制文案；解析开关可一键关闭 |
| R3 | 抓取第三方内容涉版权 | 只做内部分析，不展示原文、不落库 |
| R4 | AI 成本被刷爆 | 四级限流 + 每日预算熔断 + 缓存命中率目标 40% |
| R5 | 医疗/财经类谣言定性风险 | 该领域一律降为"说不准 + 建议咨询医生/银行官方客服" |
| R6 | 备案/算法合规时间不确定 | T+0 就启动 ICP 备案；模型选择"已备案第三方"，提前与平台确认 |
| R7 | 老年用户不会复制粘贴 | P1 加剪贴板自动读取 + 语音播报；P2 加子女代查 |

**待你确认的 3 件事**（影响 MVP 排期）：
1. 小程序主体是企业还是个人？（影响可选类目与备案）
2. 大模型用哪家（DeepSeek 成本低 / 豆包中文稳 / 混元微信生态内）？我有推荐但要你定预算口径
3. 首发要不要做链接解析？我的建议是 **P0 不做**，把 14 天全押在"文本判定准确率 + 老年化表达"上
