# 2026-09-21

## [20:50] 动作: 输出「辨是非」小程序架构方案（新建项目）

- 项目定位：面向老年用户的谣言/骗局识别小程序，粘贴内容 → AI 判定 → 极度精简口语化结论。
- 产出文件：`docs/架构方案.md`（9 章：选型、总体架构、前端页面与交互、云函数与 AI 链路、数据模型与接口、审核合规、MVP 分期、增长、落地清单、风险）。
- 技术选型决策（本项目约定）：
  - 小程序原生 + 微信云开发（云函数/云数据库/云存储），不引入 Taro/uni-app。
  - 云函数内用 `cloud.getWXContext()` 取 openid 鉴权，不自建 token 体系。
  - 异步任务模型：`analyze` 同步返回 jobId，前端用 `db.collection('jobs').doc(id).watch()` 实时收进度，失败降级 2s 轮询（云函数超时上限 60s 的规避方案）。
  - AI 链路四阶段：链接解析 → AI 定级 → 官方佐证（与定级并行）→ 老年化改写；输出严格 JSON；冲突一律降「说不准」。
  - 缓存：内容 sha256 指纹 + SimHash 相似命中，按结论分层 TTL（假 7 天 / 真 30 天 / 存疑 24h）。
  - 降级三级：L1 抓取失败看标题、L2 规则引擎兜底、L3 反诈五要素自查清单；永不空白返回。
- 合规要点（重要，后续别踩）：ICP 备案、AI 生成内容显式标识（2025-09-01 标识办法）、`msgSecCheck`、来源域名白名单、禁止以官方自居、不用「医疗/新闻」类目。
- 建议的 MVP 边界：P0（14 天）只做纯文本 + 短信，**不做链接抓取**；抖音/小红书解析放 P2 且做成可开关。
- 未决事项（等用户确认）：小程序主体类型（企业/个人）、大模型选型（DeepSeek/豆包/混元）、首发是否做链接解析。
